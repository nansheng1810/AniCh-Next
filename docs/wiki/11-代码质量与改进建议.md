## 11.2 P0：已修复（1.1.0）

> 以下 7 项在 1.1.0 中已全部修复，代码片段保留作回归参考。

### 11.2.1 收藏页分页类型强转错误 ✅

文件：[bangumi_collection/controller.dart](../../lib/src/pages/bangumi_collection/controller.dart#L78)

```dart
page((data.body?.next as bool ? data.body!.next : 0) as int?);
```

- `next` 在 JSON 模型中为 `bool?`（是否还有下一页），旧代码又把它强转为 `int?`，只要为 `true` 就抛 `TypeError`。
- 该表达式在 [bangumi_collection/controller.dart](../../lib/src/pages/bangumi_collection/controller.dart) 与 [thread_collection/controller.dart](../../lib/src/pages/thread_collection/controller.dart) 中共 18 处。

**已修复**：`get` / `reload` 按第一页处理，`more` 在当前页基础上递增：

```dart
page((data.body?.next == true) ? 2 : 0);          // get / reload
page((data.body?.next == true) ? page.value + 1 : 0); // more
```

### 11.2.2 播放页跳转详情使用了错误的 id ✅

文件：[bangumi_vod/views/index.dart](../../lib/src/pages/bangumi_vod/views/index.dart#L50)

```dart
Get.toNamed('/bangumi/${controller.episode}', arguments: controller.data);
```

- 路由 `/bangumi/:id` 期望的是**番剧 id**，这里传的是**集数**，导致点标题跳到另一部番剧或详情页加载失败。
- 已改为 `controller.data.id`（模型 `BangumiDetailModel` 的 id 字段）。

### 11.2.3 `ThemeMode.values` 越界 ✅

文件：`lib/main.dart:89`、`lib/src/pages/settings/storage/theme_storage.dart:20`

```dart
themeMode: ThemeMode.values[ThemeSettingsStorage.themeMode.value],
```

- 磁盘中的 `themeMode` 若为负数或 > 2，启动即抛 `RangeError`。
- 已修复：`ThemeSettingsStorage.init()` 校验存储类型并 clamp，`main.dart` 读取时再次 clamp。

### 11.2.4 搜索面板参数非空断言 ✅

文件：[search_panel/controller.dart](../../lib/src/pages/search_panel/controller.dart#L18)

```dart
searchType = Get.arguments['type']!;
```

- 任何未带 `type` 的调用都会抛空指针。
- 已修复：改为带默认值的安全读取。

### 11.2.5 观看记录读取无保护 ✅

文件：[play_history_storage.dart](../../lib/src/pages/settings/storage/play_history_storage.dart#L32-L41)

```dart
final thisEpisode = history['episodes'].firstWhere(
    (e) => e['episode'].toString() == episode.toString(),
    orElse: () => {});
return int.parse((thisEpisode['position'] ?? 0).toString());
```

- 若 `episodes` 不是 List、元素不是 Map、或 `position` 是非数字字符串，都会抛异常，导致播放页初始化中断。
- 已修复：读取时增加类型判断与默认值，异常数据不再中断播放页初始化。

### 11.2.6 Android 构建被签名文件阻断 ✅

文件：`android/app/build.gradle:27-29`

```groovy
def keystorePropertiesFile = rootProject.file("key.properties")
```

- 仓库缺少 `android/key.properties`，旧版 Gradle 配置阶段直接失败。

## 11.3 P1：功能缺陷与明显错误

### 11.3.1 默认弹幕屏蔽形同虚设

文件：[danmaku_shield/storage.dart](../../lib/src/widgets/danmaku_shield/storage.dart#L68-L88)

```dart
static List<String> defaultList = [];
```

- `defaultShieldCheck(data)` 遍历恒空的 `defaultList`，所有弹幕都会被保留。
- 注释中提到「避免在 compute isolate 中使用静态字段」，因此这个默认列表也无法在 isolate 内生效。
- 修复：把默认词表作为常量传入 isolate，或删除该函数并只保留用户屏蔽词路径。

### 11.3.2 `account_storage.dart` 类名冲突

文件：`lib/src/pages/settings/storage/account_storage.dart:5`

```dart
class ThemeSettingsStorage { ... }
```

- 与 `theme_storage.dart` 的 `ThemeSettingsStorage` 同名；当前无人导入，但一旦同时引用即编译失败。
- 修复：删除该文件（其中 `avatar` 逻辑未被使用），或重命名为 `AccountSettingsStorage` 并接入。

### 11.3.3 五套设置页 Controller 是空壳

文件：[settings/controller.dart](../../lib/src/pages/settings/controller.dart)

- `ThemeSettingsPageController`、`AccountSettingsPageController`、`DanmakuSettingsPageController`、`PlayHistorySettingsPageController`、`InfoSettingsPageController` 各只创建 `AnimationController`，无任何业务方法。
- 设置页实际状态都在静态 Storage 类里，这些 Controller 属于多余层。
- 修复：删除 Controller，页面直接用 `Obx` 读 Storage；需要动画时在 Widget 内用 `SingleTickerProviderStateMixin`。

### 11.3.4 离线缓存已实现，但仍有边界限制

- `DownloadManager`（`lib/src/pages/download/download_manager.dart`）已提供任务持久化、暂停/继续、取消/删除与本地文件优先播放；下载页与个人中心入口均已接入。
- 当前只支持直链视频，`.m3u8` 会提示暂不支持；暂停后继续会从头下载。
- 下载过程仅在状态变化时写盘，进度本身不持久化，应用被杀后进度归零。

### 11.3.5 播放页重复订阅同一批流

文件：`lib/src/pages/bangumi_vod/controller.dart` 的 `listen()` 与 `lib/src/widgets/player/controller.dart` 的 `initStream()`

- 两处都监听 `player.stream.error` / `completed` / `playing` / `position`，同一事件被处理两次。
- 弹幕发射逻辑在 `listen()`，`initStream()` 又订阅了 `position` 做调试/状态更新，存在重复开销。
- 修复：明确职责边界——`PlayerController` 只维护播放器状态，`BangumiVodPageController` 只处理业务（弹幕、历史），避免同一流被两个 `listen` 消费。

### 11.3.6 主题切换不即时生效

- `isDynamic` / `styleColor` 只在 `MyApp.build()` 中读取一次，设置页修改后根 Widget 不重建。
- `setThemeMode` 通过 `Get.changeThemeMode` 生效，但另两项不会。
- 修复：用 `Obx` 包裹 `DynamicColorBuilder` 的返回值，或在 setter 中 `Get.forceAppUpdate()` / 重建根节点。

### 11.3.7 版本号解析过于脆弱

文件：`utils/utils.dart:338-348`

```dart
final currentVersion = packageInfo.version.split('.');
final latestVersion = versionInfo.data['name'].split('.');
int.parse(currentVersion[2]);
int.parse(latestVersion[2]);
```

- 要求两端都严格为三段数字；接口返回 `1.0.1-beta`、`v1.0.1` 或两段即抛异常，用户只会看到「检查更新失败」。
- 修复：用正则提取数字段，缺失段补 0；或直接使用已有的 `Utils.parseVersion`（同样有 `int.parse` 风险，需要容错）。

### 11.3.8 空列表取 `last`

| 位置 | 代码 | 风险 |
| --- | --- | --- |
| `HomeAllController.more()` / `HomeArtworkController.more()` / `HomeCosplayController.more()` | `skip: result.last.id` | 首次加载失败或返回空时 `StateError` |
| `CommentController.getMoreComments` | `skip: comments.last['id']` | 同上 |
| `ThreadPageController.more()` 等多处 | `result.last` | 同上 |

修复：`if (result.isEmpty) return;` 或使用 `result.lastOrNull`。

### 11.3.9 弹幕设置的热更新依赖重建

- `PlayerController.updateDanmuOption` 每次接收新 `DanmakuOption`，但播放页在 `listen()` 的 `playing` 事件里才刷新开关状态，非播放状态修改设置可能不立即应用。
- 建议在弹幕设置面板的 `onChanged` 中直接调用 `updateDanmuOption`。

## 11.4 P1：性能问题

### 11.4.1 弹幕引擎 1ms 定时器

文件：[danmaku_view.dart](../../lib/src/widgets/ns_danmaku/danmaku_view.dart)

```dart
_timer = Timer.periodic(const Duration(milliseconds: 1), (e) {
  if (_controller.running) {
    _runTime += 0.001;
  }
});
```

- 每秒 1000 次回调，即使暂停也在空转；移动端会增加唤醒与耗电。
- 修复：使用 `Ticker`（与帧同步，60/120fps 足够平滑），或把周期改为 16ms（约 60fps）。

### 11.4.2 弹幕发射 O(n) 全表扫描

文件：`lib/src/pages/bangumi_vod/controller.dart` 的 `player.stream.position.listen`

```dart
final currentDanmakuList = danmakuList.where((e) {
  return double.parse(e.time.toStringAsFixed(1)) == currentPosition / 10 &&
      DanmakuShieldStorage.shieldCheck(e.text);
});
```

- 每 100ms 对**四个来源的全量弹幕列表**各做一次 `where`，复杂度 O(4n)。
- 一部番剧的 B 站弹幕可达数万条，长时间播放会持续占用主 isolate。
- 修复：加载后按「0.1 秒桶」建立 `Map<int, List<DanmakuItem>>` 索引，播放时 O(1) 取桶；屏蔽词在入库前预处理。

### 11.4.3 观看记录整条重写

- 每 5 秒把整个番剧 Map（含所有集数）序列化写入 `playHistory` Box。
- 修复：拆分键（`<id>.<episode>`）只写当前集，或降低写入频率到 15–30 秒并在 `onClose` 强制落盘。

### 11.4.4 图片缓存上限偏大

文件：`lib/main.dart:38-39`

```dart
PaintingBinding.instance.imageCache.maximumSize = 1000000;
PaintingBinding.instance.imageCache.maximumSizeBytes = 300 << 20; // 300MB
```

- 300MB 图片缓存对中低端移动设备过高，容易触发系统内存回收。
- 建议移动端 80–120MB、桌面端 200MB，并按平台分支。

### 11.4.5 每个 API 文件独立 `Dio` ✅

- 已统一为 `lib/src/utils/account.dart` 的 `createApiDio()`：`connectTimeout 10s`、`receiveTimeout/sendTimeout 20s`、`User-Agent` 与动态 `_` 鉴权头拦截器，并对幂等 GET 自动重试一次。
- 仍保留两个独立 `Dio`：B 站弹幕代理与 QQ 视频 API（不同 baseUrl，无需鉴权）。

## 11.5 P1：安全与隐私

| 问题 | 位置 | 建议 |
| --- | --- | --- |
| Token / user 明文存储 | GetStorage 默认 Box | 使用 `flutter_secure_storage` 存 token；user 可保留明文但去除敏感字段 |
| 用户输入直接作为正则 | `danmaku_shield/storage.dart:51` | 限制长度、禁止嵌套量词，或使用 `RegExp` 超时包装 |
| 鉴权头是 Protobuf 字节 CSV | `utils/account.dart` | 属于自定义协议，依赖 TLS；确保所有请求走 HTTPS（当前 baseUrl 为 https） |
| 日志可能包含响应体 | `Log.d` 打印完整响应 | 发布版关闭 `writeFile` 或脱敏 |
| 更新地址依赖仓库名 | `apis/info.dart:13` | 当前指向 `nansheng1810/AniCh-Next`，仓库改名时需同步更新，避免检查更新 404 |
